# Proposal

## Why

当前 2021 期来自 130 条原始记录、清洗后约 122 条的大厂技术岗样本，城市覆盖有限，难以支撑现有薪资、地域和学历经验分析。用户已确认采用 2020 年公开的多城市 IT 岗位样本替换它，保留 2018 期，并接受新一期缺少技能数据的限制。

## What Changes

- 接入 `ccclll777/bosszp` 的 `job_data_clean_price.csv`，固定到提交 `2dcc08a8ff0c79a0afda3d150c1a9618ebe6e390`；探索阶段实测 28,162 条、12 个城市、10 个搜索岗位类别，去重后预计约 2.48 万条，最终数量以现有清洗流程实测为准。
- 为 CSV 来源增加显式数值月薪上下限适配，把元/月数值转换成公共清洗流程可识别的带单位薪资，避免裸数被当成千元。
- **BREAKING**：当前可用快照由 `2018 + 2021` 变为 `2018 + 2020`。2020 期导入成功时，在同一事务中移除被替代的 2021 期及其派生岗位、技能记录；普通快照重导仍保持批内幂等。
- 默认展示 2020 期；旧 `snapshot=2021` 链接沿用未知期次回退逻辑，落到实际可用的最新一期。
- 页脚标注“2020 年 4 月公开快照、12 城市 IT 岗位样本、无逐条发布日期、无技能数据”，不标为 2024 年或全年全国全量。
- 更新数据获取、迁移、回滚和测试文档；2020 期技能页沿用无技能数据提示，不生成或借用技能记录。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `data-pipeline`：支持显式数值月薪 CSV；为已声明替代关系提供原子快照替换；登记可追溯的 2020 期来源与样本边界。
- `web-dashboard`：约定替换后的可用期次、默认展示和旧链接回退，补充公开快照时间与覆盖范围标注要求。

## Impact

- 代码：`etl/sources.py`、`etl/run_etl.py`、`etl/repository.py`；公共清洗规则、查询层与五个页面尽量复用。
- 数据：新增本地原始 CSV，继续放在被 Git 忽略的 `data/raw/`；只替换 2021 期派生数据，不重建整库，不更改 2018 期、账号或验证码数据；无需新增表或列。
- 验证：来源适配单元测试，独立 MySQL 测试库中的原子替换、回滚、幂等、隔离与页面回归；实际数据质量核验。
- 文档：`README.md`、`data/README.md`、`data/sample_values.md`、`docs/etl.md`、`docs/run.md`。
- 依赖：沿用 pandas、PyMySQL 与现有标准库，不增加运行依赖。
