## 应用与连接的生命周期

`create_app()` 只配置和组装应用，不连接数据库。首次运行或升级后，显式执行 `python -m app init-db`；它使用 `CREATE TABLE IF NOT EXISTS` 创建所需表，不删除现有数据，也不承担旧表的结构迁移。

Blueprint 是 Flask 自带的路由分组机制。认证与分析路由分组后，URL 路径保持原样，内部端点名分别为 `auth.*` 和 `dashboard.*`。分析页面的数据注入只属于分析路由，登录、注册页不查询 `snapshots` 或 `jobs`。

请求第一次实际访问数据库时，连接保存到 `flask.g`，后续查询复用；应用上下文结束时由统一回收函数关闭。命令行调用自己创建、关闭连接，写入操作自己提交或回滚。快照列表在一次分析请求内只读一次，既供筛选解析，也供页脚与下拉使用。

## 统计与事务

页面使用 `get_group_stats(..., include_median=False)`，让 MySQL 直接计算数量和平均数，只返回分组结果。需要中位数的调用继续使用默认接口，读取薪资明细由 pandas 计算；统计口径与快照隔离规则保持一致。

注册以唯一索引作为最终查重依据，将重复键错误转换成“用户名已被占用”，并发请求也使用同一规则。

验证码答案和到期时间存于 `captcha_challenges`；浏览器签名 Cookie 只保存随机挑战标识。消费时通过 `SELECT ... FOR UPDATE` 锁定记录，读取后删除并提交，再判断答案是否正确和是否过期。因此答案错误也会消费挑战，并发请求及旧 Cookie 都不能让已消费记录恢复。刷新会撤销旧标识，过期记录在创建新验证码时清理。有效期按 MySQL 的 UTC 时间计算，为 5 分钟。

ETL 在来源校验和清洗成功后才修改快照内容。快照元数据更新、删除本期旧数据、写入新岗位和技能在同一事务内完成；中途失败则整体回滚。

2020 来源显式声明元/月数值上下限，适配为带单位的薪资后复用公共清洗流程。它通过受控的 `replaces: "2021"` 声明替代旧样本；写入 2020 与移除 2021 的岗位、技能和元数据一并提交或回滚，2018、账号和验证码不参与该事务的变更。2020 不含技能明细，搜索类别不用于推断技能。
